# نظام شؤون الموظفين (Firebase + GitHub Pages)

لا يوجد تخزين محلي: كل البيانات والحسابات على Firebase، والموقع يُنشر من GitHub.

## 1) إعداد Firebase (مرة واحدة)
1. أنشئ مشروعاً في https://console.firebase.google.com
2. **Build ← Authentication ← Sign-in method**: فعّل **Email/Password**.
3. **Build ← Firestore Database**: أنشئ قاعدة بيانات (Production mode).
4. **Firestore ← Rules**: الصق محتوى `firestore.rules` واضغط Publish.
5. **Project settings ← Your apps ← Web (</>)**: انسخ الـ config وضعه في `js/firebase-config.js`.
6. **Authentication ← Settings ← Authorized domains**: أضف نطاق GitHub Pages (`USERNAME.github.io`).

## 2) الرفع على GitHub
```
git init && git add . && git commit -m "HR system"
git branch -M main && git remote add origin https://github.com/USERNAME/REPO.git && git push -u origin main
```
ثم **Settings ← Pages ← Source: GitHub Actions**. كل push يشغّل الاختبارات ثم ينشر الموقع على `https://USERNAME.github.io/REPO/`.

## 3) أول تشغيل
افتح الموقع ← **أول تشغيل؟ إنشاء حساب المدير**. يعمل مرة واحدة فقط؛ بعدها أضف المستخدمين من الإعدادات.

## تسجيل الدخول
- اسم المستخدم: حروف أو أرقام (عربي/إنجليزي). كلمة المرور: أرقام فقط (4–20) وتقبل ٠١٢٣٤٥٦٧٨٩.
- داخلياً يُحوَّل اسم المستخدم إلى بريد وهمي ثابت (`hash@hr-system.app`) لأن Firebase Auth يتطلب بريداً. كلمة المرور تُضاف لها بادئة لتبلغ حد Firebase الأدنى (6).
- نسيان كلمة مرور المستخدم: يحذفه المدير وينشئ حساباً باسم مختلف، أو تُعاد من Firebase Console.

## الأمان (مهم)
- قواعد Firestore تحصر القراءة/الكتابة بالحسابات المسجلة فقط. صلاحيات الشاشات التفصيلية تُطبَّق في الواجهة (لا على الخادم)؛ فمن لديه حساب يستطيع تقنياً قراءة كل البيانات عبر Firebase مباشرة. الحسابات الموثوقة فقط.
- مفتاح `apiKey` في الإعداد ليس سراً؛ الحماية من القواعد.
- كلمة مرور رقمية قصيرة ضعيفة أمام التخمين؛ يفضّل 8 أرقام فأكثر.

## البصمة الذاتية للموظفين
1. **الإعدادات ← البصمة الذاتية**: وقف في مقر العمل واضغط "استخدم موقعي الحالي"، حدّد نصف القطر (افتراضي 100 م) وفعّل الخيار ثم احفظ.
2. **حسابات الموظفين تلقائية**: عند إضافة موظف له حضور وانصراف يُنشأ حسابه فوراً (اسم المستخدم = رقم موبايله، وكلمة المرور الافتراضية 1234 أو ما تكتبه في نموذج الموظف) وتظهر لك بياناته مع زر واتساب لإرسالها. للموظفين الحاليين: الإعدادات ← حسابات دخول الموظفين ← إنشاء حسابات. يدخل الموظف من الرابط فتظهر له شاشة البصمة وسجل حضوره فقط (لا يرى أي بيانات أخرى).
3. **القواعد**: الحضور المبكر يُثبَّت عند بداية الوردية (بلا إضافي)، والتأخر يُخصم، والانصراف بعد نهاية الوردية يُحتسب إضافياً. البصمة مسموحة من (بداية الوردية − 30 د) حتى نهايتها، والانصراف حتى 4 ساعات بعدها (قابلة للتعديل).
4. وقت البصمة يُسجَّل من خادم Firebase. تظهر البصمات في سجل الحضور عندما يكون جهاز إداري مفتوحاً على النظام. الحضور اليدوي يعمل كما هو، وله الأولوية على البصمة إن وُجد.
5. يلزم **نشر `firestore.rules` من جديد** لأنه تغيّر. الموقع يعمل على HTTPS فقط (GitHub Pages مناسب).
6. حد التحقق: الموقع يُفحص في متصفح الموظف، ويمكن نظرياً تزييفه ببرامج خاصة. راجع سجل الحضور (يُسجَّل بجانب كل يوم وقت البصمة والمسافة).

## الدخول ببصمة الجهاز
- من أي حساب (مدير أو موظف): زر **الدخول بالبصمة** (👆) ← أدخل كلمة المرور مرة للتأكيد ← يطلب الهاتف البصمة أو الوجه. بعدها تظهر على شاشة الدخول في هذا الجهاز خانة **الدخول بالبصمة**.
- تعمل على https فقط (GitHub Pages مناسب) وعلى أجهزة فيها بصمة أو قفل شاشة.
- بيانات الدخول تُحفظ على هذا الجهاز فقط، مشفّرة بمفتاح غير قابل للتصدير، ولا تُفك إلا بعد نجاح تحقق بصمة الجهاز. هذه طريقة راحة وليست مفتاح Passkey حقيقي مرتبطاً بالخادم (ذلك يحتاج Cloud Functions وخطة Blaze).
- تغيير كلمة المرور أو تغيّرها من المسؤول يُلغي التفعيل تلقائياً، فيفعّلها المستخدم من جديد.
